# 画像から部位ごとのコマを作る

## 使い方

メディアの画像一覧で画像を1枚選び、「部位コマを作る」を開く。画像をドラッグで囲み、部位名を付けて「コマを作る」を押す。囲み直す時は、その部位を消して選び直す。マウスとタッチの両方で操作できる。

作成するのは普通のキャラクターコマで、HPや名前はそれぞれ独立している。位置は元画像の部位の並びを目安に、テーブル中央へ置く。以後は各コマを自由に動かせる。連動移動や、部位を束ねる新しいモンスターデータは作らない。

## 画像と保存

元画像は残す。選んだ範囲を切り抜き、縦横比を保つために正方形の透明な余白を付ける。画像の登録には既存の処理を使い、小さくなる場合はWebPへ変換される。切り抜きは1辺4,096pxまで、画像1枚あたりの上限は通常と同じ2MB。アニメーション画像を使った場合も、作成する部位画像は静止画になる。

部位画像は通常の画像一覧に加わる。「全て」か「キャラクター」のタグで見つけられる。キャラクターと画像は既存の同期・卓ZIP・キャラクターZIPで扱い、新しい保存属性や形式を増やさない。作成時の範囲は保存しないため、後から元画像との対応を編集する機能はない。

GMが作るコマには通常のGM作成時の公開範囲が適用される。秘匿画像の選択も画像一覧と同じ権限で制限する。既に登録済みの同一画像やタグの設定は上書きしない。

## 作成の条件と制限

- 一度に選べるのは20部位まで。範囲は画像内で縦横2px以上、名前は80文字以内。
- すべての部位画像を準備してから卓へ追加する。切り抜きに失敗した場合は、範囲を残してやり直せる。
- 準備中に画面を閉じた、画像が消えた、編集権限や表示テーブルが変わった場合は、コマを作らない。
- 外部URLの画像は、提供元がCanvasでの読み取りを許可している場合に使える。読み取れない場合はファイルから登録する。
- 自動の部位判定、範囲の移動・拡縮、連動移動は含めない。画像を一度囲んでコマを作る操作を対象にしている。

## 変更範囲と依存

基点：`cebe74686438b29ee4a3eb2d927621963d22154d`。ブランチ：`codex/multipart-character-tokens`。

画像内座標の計算はdomain、Canvasの切り抜きはinfrastructure、画像の準備とコマ作成はapplication、範囲選択の画面はfeatures/fileに置く。通常の画像上限を既存のFileArchiverから定数として共用する。画像一覧の選択・秘匿表示と、TabletopActionServiceの標準キャラクター作成を使う。

基点には先行の私家機能が含まれるが、この処理はルビ・カットイン・共有メモの整形に依存しない。公式へ移す時は、画像一覧の選択方法と権限判定を公式側へ合わせる必要がある。新しい依存パッケージはない。

## 確認

座標変換、逆方向のドラッグ、範囲制限、透明な余白、画像準備の失敗と中断、独立HP、標準キャラクターのXML、権限の関連テストを実施した。Chromiumでは画像登録から2部位の作成、名前、元画像の保持、取り消しを確認した。関連のAngular環境5ファイル82件、通常コミットフック263ファイル4,530件、Chromium2件で成功した。ブラウザでは生成画像の透明部分と中央の画素も確認した。型検査・変更ファイルのlintと整形検査・production buildも成功。

別端末での表示、卓・キャラクターZIPの保存と再読み込み、タッチ端末での実操作は利用者の確認対象。

## 紹介文案

登録した画像を囲み、部位ごとのキャラクターコマを作れます。元画像を残し、HP・名前・移動は各コマで独立。通常の卓データとして保存できます。
