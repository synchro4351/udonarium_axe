# カットイン文字の 1 字ずつの動きを細かく決める

## 目的と使い方

文字レイヤーの「1字ずつ」に、順番・速さ・向き・傾け方・退場を足した。文章は 1 つの文字列のまま編集する。字ごとのキーフレームは打たない。

1. シーン編集で文字レイヤーを選ぶ。
2. 「ふわっと」「弾む」「波打つ」のどれかを押す。細かい設定は既定に戻り、その動きが入る。ここまでで足りることが多い。
3. 足りなければ「文字ごとの詳細」を開き、出現順（先頭から・末尾から・中央から）、1字ごとの遅れ、1字の動き、入ってくる向き、傾け方、退場とその長さを決める。
4. 再生ボタンか時刻欄で確かめる。気に入らなければ Ctrl+Z で 1 項目ずつ戻す。

「1字ずつ」の選択肢には、従来の「ポンと出る」「波打つ」「震える」に加えて「順にフェード」「順にすべり込む」が入った。詳細を開かない限り、項目は増えて見えない。

## 再生のされ方

- `{character}` を再生時のキャラクター名へ置き換えてから字を数える。順番の基準は置き換え後の字数になる。
- 肌の色を付けた絵文字や結合した絵文字は 1 字として動く。改行は字数に入らず、行をまたいでも順番は通しで数える。
- 退場は、レイヤーの終了時刻（終了 0 ならシーンの最後）までに最後の字まで終わる。間に合わないときは、退場する字の間隔だけを詰める。登場は詰めないので、長い文章では遅れを短くする必要がある。
- 動きはシーンの時計に乗る。再生位置の移動、ループ、リプレイでの途中からの再生でも、レイヤーと字の時刻はそろったまま。
- 入ってくる向きは「ポンと出る」「順にすべり込む」に効く。「順にフェード」はその場で濃くなるだけで、「波打つ」「震える」は向きを使わない。

## 変更範囲

基点：`75b16b3a52adfe214953e9b995872b6d1096f18e`。ブランチ：`codex/cutin-letter-animation-controls`。

- 文字の動きの計算（`domain/media/cut-in-text.ts`）：字の順位、時間の範囲制限、退場の時刻、字ごとのフレーム。字ごとのフレームは最大 360 枚のまま。レイヤー全体では 24,000 枚前後を目安にし、字数が多いときは 1 字あたりの枚数を減らす。ただし 1 字の動きが崩れないよう、どの字にも少なくとも 30 枚は割り当てる。このため 800 字を超える文章では目安を上回る。登場と退場の始まりと終わりの時刻は、どの場合もフレームに残す。
- レイヤー（`cut-in-layer.ts`）：同期する項目を 7 つ追加。
- 取り消し用のスナップショット（`cut-in-scene-snapshot.ts`）：新しい 7 項目を記録対象に加えた。これがないと、詳細の変更を Ctrl+Z で戻せなかった。
- レイヤー設定欄：簡単なボタンを先に置き、詳細は折り畳む。いまの動きと退場で効かない項目は操作できなくする。入ってくる向きは「ポンと出る」「順にすべり込む」、1字の動きは「ポンと出る」「順にフェード」「順にすべり込む」、退場の長さは退場ありのときだけ。1字ごとの遅れは、登場する 3 種類か退場ありのときに使える。出現順・傾け方・退場は常に選べる。無効にした項目も値は消さず、動きを戻せば元の値で効く。閲覧専用では、ボタンも詳細もすべて操作できない。
- ステージ：字数を表示中の文字から数え、退場の締め切りを既存の `layerWindow` から取る。
- 初回に表示する時刻の選び方（`cut-in-poster-frame.ts`）：「順にフェード」「順にすべり込む」の登場と、退場中の字も「まだ途中」として避ける。
- ja/en/ko の文言、単体テスト、ブラウザテスト、利用ガイド。

## 保存と同期

7 項目はレイヤーの属性として保存し、ほかの項目と同じ経路で同期する。保存先の XML にはそのまま属性が増える。

| 属性                   | 既定        | 範囲・値                         |
| ---------------------- | ----------- | -------------------------------- |
| `letterOrder`          | `forward`   | `forward`・`reverse`・`center`   |
| `letterIntervalMs`     | `60`        | 0〜1000                          |
| `letterDurationMs`     | `260`       | 50〜3000                         |
| `letterTiltMode`       | `alternate` | `alternate`・`uniform`           |
| `letterExit`           | `none`      | `none`・`fade`・`shrink`・`rise` |
| `letterExitDurationMs` | `260`       | 50〜3000                         |
| `letterDirection`      | `up`        | `up`・`down`・`left`・`right`    |

既定値は従来の「ポンと出る」「波打つ」「震える」の動きそのもので、属性を持たない古いカットインは前と同じに動く。知らない値、空の値、数値にならない値は既定として再生する。範囲外の数値は端に丸める。

新しい項目を知らない古い版の参加者の画面では、追加の動きは再生されない。「順にフェード」「順にすべり込む」と退場だけの指定は、字がまとめて表示される。順番の指定も無視され、先頭から動く。属性はレイヤーの属性表にそのまま残るため、古い版で別の項目を編集しても消えない想定。ただし古い版どうしでの確認はしていない。

## 依存

新しいパッケージは使わない。字の分割は既存の書記素分割（`graphemesOf`）、アニメーションはブラウザの Web Animations API、変更の通知は既存の `versionOf` を使う。

## 制限

- リプレイの動画書き出し（Canvas 描画）は文字を行ごとにまとめて描く。1 字ずつの動き・傾き・退場は動画に入らない。従来の「ポンと出る」などの動きと字の傾きも、もともと入っていなかった。
- OS の「動きを減らす」設定が効いている端末では、字は止まった状態で表示する。
- 文字レイヤーの改行は、XML 属性へ書き出すときに空白へ置き換わる。部屋やカットインを保存して読み直すと、複数行の文章が 1 行になる。単体テスト（happy-dom）と Chromium の XML 解析の両方で、属性内の改行が空白になることを確かめた。レイヤーの複製も XML を経由するので、同じく改行が消える。部屋の同期では改行が残る。この変更より前からある保存処理の問題で、ここでは直していない。
- 1 字ずつのキーフレーム編集や、字ごとに別の設定を持たせる機能は含めない。
