# 多部位キャラクターの使い勝手改善

連動する多部位キャラクター（`TYOITASHI_LINKED_MULTIPART.md`）の実卓確認で出た要望をまとめて扱います。範囲選択の重なり許可と調整、エフェクトの着弾位置、名前・リソース・バフの表示位置、連動移動のずれの調査です。

- ブランチ：`codex/multipart-usability`

- README掲載文案：部位コマの範囲を重ねて選べるようになり、選んだ範囲は角や辺のハンドルで動かしたり大きさを変えたりできます。エフェクトは対象の部位の位置に出ます。キャラクター名・リソース・バフの表示位置は、通常のキャラクターも含めて頭上と画像内9か所から選べます。

## 1. エフェクトが部位の位置に出ない

**原因**：再生側はすでに閲覧者ごとの部位位置（`MultipartGroupService.anchorOf`）を作ってキャストに入れていました。ところが描画側の `TableEffectOverlayComponent.centerOf` が、追従するエフェクト（`followTarget`、既定で有効）の対象を毎フレーム「コマ全体の中心」へ引き直し、キャストの座標を上書きしていました。そのため部位を狙っても元画像の中央に出ていました。

**修正**：`centerOf` が連動部位だけ `anchorOf` を使います。閲覧者のカメラ（回転・傾き・2D表示・セル内表示）で計算するので、発信者の座標は使いません。共有する `EffectCast` は書き換えません。通常のキャラクターは従来の中心のままです。

**テスト**：`table-effect-overlay.component.spec.ts` に、実際の描画コンポーネントと実サービスで、同じ位置の通常コマと右半分の部位が別の位置に着弾することを確認するケースを追加しました。修正を外すと 437.5 のはずが 425 になって失敗することを確認しています。ブラウザのE2Eは書いていません（効果の再生を起動する操作が重いため）。

**残る制限**：崩れる・斬られるなど、コマの絵そのものを砕く演出は、部位でも元画像全体を使います。部位だけを切り抜く対応はしていません。

## 2. 範囲の重なり

重なりの拒否を、画面・作成処理・メッセージ・テストから外しました。画像の範囲内であること、縦横2px以上、名前、20部位までの条件は残しています。重なった画素は両方の部位の画像に入ります。画面上で重なった場所を押すと、あとから作った（上に描かれた）範囲が選ばれます。`feature.file.multipart.overlap` の文言は削除しました。保存形式は変わりません。

## 3. 範囲の移動とリサイズ

- 範囲を囲むと、その範囲が選ばれます。選択中の範囲は黄色の太い枠になり、四隅と四辺の中央に白い小さな点（ハンドル）が出ます。
- 保存済みの範囲を押す（動かさない）と選択、何もない所を押すと選択を外します。一覧の番号を押しても選べます。
- 選択中の範囲をドラッグすると、大きさを変えずに画像内で動きます。ハンドルをドラッグすると、反対側の辺を固定して大きさが変わります。反対側を越えると範囲が反転します。最小は2pxで、画像の外には出ません。
- 押した位置から4px以上動いたときだけドラッグとして扱い、それ未満はクリックです。ハンドルの操作で新しい範囲ができることはありません。キャンセルで中断すると元の範囲に戻ります。
- 今までどおり、選択していない場所から囲み始めると新しい範囲を作ります。選択中の範囲の内側から囲み始めると移動になるため、新しく囲みたいときは「新しい範囲」を押してからドラッグします。選択中の範囲が画像全体を覆っていても、このボタンで新しい範囲を作れます。
- 座標は元画像の画素で保持し、表示サイズから換算します。マウスとタッチの両方で動きます。ハンドルの当たり判定は見た目より広くしています。

純粋な計算は `domain/character/image-part.ts`（`topmostImagePartAt`、`moveImagePart`、`resizeImagePart`）、操作は `features/file/multipart-character` に置いています。

## 4. 名前・リソース・バフの表示位置

キャラクターシートの設定タブに、1つの選択欄「名前などの位置」を足しました。選べるのは「頭上（既定）」と画像内9か所（「中央」「上」「下」「左」「右」「左上」「右上」「左下」「右下」）です。数値入力はありません。

- 名前・リソースバー・バフと数値変化の表示は、1つのまとまりとして一緒に動きます。まとまりは画像（部位なら部位の範囲）の内側に置き、画像の目標位置やエフェクトの着弾点は動きません。通常キャラクターも表示位置を変えた後にバフ表示の切り替えを使え、詳細表示では従来どおり各バフを表示します。
- 部位は、これまでどおり範囲の内側の上中央に出します。そのため部位では「頭上（既定）」と「上」は同じ位置です。
- 通常のキャラクターは、既定のままなら従来の表示（頭上に浮かぶ名前・バー・バフ）で何も変わりません。既定以外を選ぶと、同じ小さなまとまりを画像の内側に置きます。画像の形に合わせた範囲を使い、セル内表示で余白ができる場合も画像の実寸を基準にします。
- 名前を隠す・バフを隠す・秘匿されたリソースの扱いは従来どおりです。編集権限のない人は選択欄を変えられません。
- 通常のキャラクターで既定以外を選んでも、バフ表示の切り替えボタンと詳細表示は使えます。ポスター表示と多方向（マルチアングル）表示は従来の配置のままで、この設定は効きません。
- 保存は `GameCharacter` の通常の同期属性 `labelPlacement` 1つです。空または未知の値は既定として読みます。部屋ZIP、キャラクターZIP、複製はすべてこの属性を通常どおり持ち運びます。属性のない古いデータは既定のまま読めます。

## 5. 連動する部位の移動のわずかなずれ

調べた結果、原因は2つに分かれました。

1. **手元でのドラッグ（実際の欠陥・修正済み）**：ドラッグ中、動かしているコマはアニメーション（`transform 132ms linear`）を外しますが、一緒に動く他の部位には以前の移動で付いたこの132msのアニメーションが残っていました。このため手元では、他の部位がドラッグしているコマより最大約132ms遅れて付いてきていました。ドラッグの開始時に一緒に動くコマのアニメーションを外し、終了時に戻すようにしました（`MultiMovableService`）。選択した複数コマの移動にも同じ効果があります。座標の計算自体は同じフレーム内で全員に当てており、ずれはありませんでした。
2. **他の参加者側（仕様上の差・対応しない）**：部位は1コマ1オブジェクトとして別々の通信で届き、受け取った側は到着したものから132msの移動アニメーションを始めます。通信の到着間隔と描画のまとめ処理によって、部位ごとに数十ms程度の時間差が出ることがあります。座標の最終値は揃います。まとめて送る仕組みは入れていません。「同時に描画される」ことは保証しません。

## 任意の画面確認メモ

上記の単体テストとPlaywrightのブラウザE2Eで実装を検証済みです。以下は操作を手元で確認したい場合の参考手順で、完了条件や追加の採用ゲートではありません。

1. 画像一覧で画像を選んで「部位コマを作る」を開く（またはキャラクターを右クリックして「部位に分ける」）。
2. 画像全体を範囲にしてから「新しい範囲」を押し、内側に別の範囲を作る。その後、2つの範囲を重ねて囲み、拒否されないことも確認する。
3. 範囲を1回押して選び、ハンドルの角・辺をドラッグして大きさを変える。反対側を越えて引いて反転すること、画像の外に出ないことも見る。選択範囲の中をドラッグして動かす。何も囲んでいない所を押すと選択が外れる。タッチ端末でも同じ操作をする。
4. 部位に分けて作成し、一覧を保存して、重なった範囲の部位が作られることを確認する。
5. 部位に対してエフェクトを出し、元画像の中央ではなく部位の位置に出ることを確認する。カメラを回す・傾ける・2D表示にして、別の端末でも見る。
6. キャラクターシートの設定タブで「名前などの位置」を変え、部位と通常のキャラクターの両方で、名前・バー・バフが一緒に動くことを確認する。名前を隠す設定、部屋ZIP保存、キャラクターZIP保存、複製も試す。
7. 部位を連続でドラッグして、手元で他の部位が遅れて付いてこないことを確認する。

## 公式へ取り込むときに合わせる所

- `TableEffectOverlayComponent.centerOf`：公式側に追従エフェクトの描画があれば、連動部位だけ `MultipartGroupService.anchorOf` へ分岐させる。

- i18nは `feature.file.multipart.adjustHint` / `handle` / `newRange`、`feature.inventory.settingsTab.labelPlacement*` を追加し、`feature.file.multipart.overlap` を削除した。

## 範囲と制限

チャットの発言部位、騎手、手番に関する機能は含めません。崩れる・斬られる演出での部位の切り抜き、配置の数値指定、ポスター・多方向表示での配置は対象外です。複数人が同時に同じ部位を動かす排他制御は従来どおり追加していません。
