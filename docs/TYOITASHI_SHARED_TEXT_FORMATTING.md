# 共有テキスト整形（キャラクターシート・マップマスク・カード）

基準コミットは `70fbd8b1028be73806b83a367d0f7a7caf259176`、ブランチは `codex/shared-text-formatting` です。

ノートで使えるようになった限定 Markdown とルビ記法を、同じレンダラーのまま次の三か所へ広げました。

- キャラクターシートの長文欄と、その概要表示
- マップマスクの文字
- カードの文字（卓上、手札、詳細プレビュー）

## 方針

- 解析器は増やしていません。整形は `ui/text-decoration/format-note-text` の `formatNoteText` が担い、ルビは `domain/chat/ruby-notation` が担います。
- 通常表示が既定です。整形は欄ごとに選ぶ任意の設定で、保存され、同期されます。
- 本文は書き換えません。通常と整形を切り替えても、文字は一文字も変わりません。
- 追加の部品は小さな切替 `text-format-switch`（通常 / 整形）だけです。説明文は置かず、見出し・リスト・引用・コード・ルビの短い例を textarea の placeholder に入れました。

## 保存の形（スキーマ）

| 対象 | 保存先 | 値 |
| --- | --- | --- |
| メモ（TextNote） | 既存の `textFormat`（変更なし） | `normal` / `formatted` |
| キャラクターの長文欄 | その `DataElement` の属性 `cs-text-format` | `formatted`（通常のときは属性なし） |
| カードの文字 | `text` 要素の属性 `cs-text-format` | 同上 |
| マップマスクの文字 | `text` 要素の属性 `cs-text-format` | 同上 |

- 欄の種類（`type` / `cs-field-type`）は変えていません。属性が無い古いデータは通常表示のまま開きます。
- `DataElement.textFormat` と `setTextFormat()` が読み書きの入口です。通常に戻すと属性を取り除きます。
- 整形を選ぶとき、文字の要素がまだ無いカードやマスクには空の要素を作ります。通常のまま何も入力しなければ、要素は増えません。
- 属性は XML にそのまま出入りし、複製にも付いてきます。

## 通常表示（旧来の動作）

通常表示は従来どおり `decorateChatStyleText` を使います。`>` の引用やルビなどの昔からの装飾は変わりません。切り替えの入口は `decorateTextByFormat(text, format)` の一か所です。

### 長文欄のルビ（通常表示）

キャラクターシートの長文欄と概要表示は、通常表示でも二つのルビ記法を読める形で見せます。

- 本文にルビ記法があるときだけ、textarea の代わりに読み取り用の表示を出します。ルビが無い欄は従来どおりの textarea です。
- 判定は `decorate-chat-text` の `hasRubyNotation`、描画は同じ `escapeHtmlWithRuby` です。新しい解析器はありません。出力は既存のエスケープを通り、URL は `linkify` でリンクになります。`1 <2 >0` や `2*3+4` は文字のままです。
- 表示をクリックする（または Enter を押す）と、同じ位置の textarea が開いて焦点が移り、保存された文字をそのまま編集できます。焦点が外れると、表示に戻ります。リンクのクリックは編集を開きません。
- 保存される文字は変わりません。固定された欄（`isValueLocked`）は表示のままで、編集は開きません。
- 整形表示の欄はこれまでどおり整形表示を使います。説明文は足していません。

## 整形表示の挙動

- 見出し（`#` から `###`）、`-` と `1.` のリスト、`>` の引用、行内コードとコードブロックを扱います。
- 二つのルビ記法（`|漢字《かんじ》` と `|word<ruby>`）はコードの外で働きます。コードの中は文字どおり残ります。
- `1 <2 >0` や `2*3+4` はそのまま表示されます。強調、HTML、画像、自動リンクは、既存のレンダラーと同じく扱いません。
- 出力はすべて既存のエスケープを通ります。`<script>` や `<img onerror>` は文字として表示されます。
- カードとマスクは `note-formatted-compact`（詰めた余白、リスト記号を内側に、引用は文字色に合わせる）で描きます。

## 権限と非公開

- 伏せたカードの文字は、整形表示でも空のままです。
- 伏せたカードでは切替も編集欄も使えず、`canEditCard` と `canReadCardFace` で守っています。
- 欄が固定されているとき（`isValueLocked`）は、長文欄の切替が働きません。
- GM メモやゲージの文字の見え方は、これまでの条件のままです。

## テスト

- 整形レンダラー: `decorateTextByFormat` の切替、ルビ、コード、数式、エスケープ。
- ドメイン: `DataElement`・`Card`・`GameTableMask` の `textFormat` の既定値、往復、旧データ、XML の往復。
- 実際の利用側: カード文字、マスク（卓上とシート）、キャラクターシート（メモ・カード）、長文欄、概要表示で、切り替えても本文が変わらないこと。
- 通常表示のルビ: 二つの記法、数式やタグの文字どおりの表示、URL のリンク、クリックで編集に入って本文がそのまま出ること、リンクのクリックと固定された欄では編集に入らないこと、ルビの無い欄と整形欄では textarea／整形表示のままであること。`hasRubyNotation` の単体テストもあります。
- 読み取り専用と非公開: 伏せたカード、固定された欄で切替が働かないこと。
- 実行した確認: 関連する Vitest（ドメイン、ui、対象の features）、`tsc -p tsconfig.spec.json --noEmit`、ESLint（`--fix`）、`npm run build`。

## 依存

追加の依存はありません。`marked` は既に実行時依存です。

## 制限

- 概要表示で整形した長文欄は、その場では編集できません。編集はシートから行います。
- 概要表示の切替は、`type` が `note` の欄が対象です。
- 卓上での直接編集には、切替を置いていません。
- 通常表示のルビ表示は長文欄が対象です。概要表示のメモ本体（TextNote）の通常表示は、従来どおり textarea です。
- 通常表示のルビ表示では、読み取り用の表示と textarea を切り替えるため、編集に入る瞬間に一度だけ表示が入れ替わります。Chromiumでクリック・フォーカス・編集・blurで戻る操作を確認しました。
- Claudeによる関連Vitest・型検査・lint・buildを受領後、CodexがPrettierとAngular builderによる利用側8ファイル282件を補完し、成功しました。通常表示のルビ補足は関連31ファイル712件も成功しています。本流統合後、Chromiumで長文ルビの編集、カードの整形・通常切替・伏せた文字の非表示、従来の縁取りと改行を確認しました。

## ブラウザ回帰の補足

初期参加者はPLで、部屋のカード編集は既定で禁止です。古い`card-text-outline`はこの前提を指定せず編集メニューを探していました。編集前にGMへ切り替えるよう、テストだけを修正しました。製品の権限は変更していません。整形の見出し・リスト・引用・コード・ルビ、数式記号の文字表示、元本文の保持、伏せたカードの非表示を同じブラウザテストで確認します。
